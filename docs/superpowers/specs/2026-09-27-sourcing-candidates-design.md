# 소싱 후보 수집기 (`/sourcing/candidates`) — 설계 스펙

날짜: 2026-09-27
승인: 사용자 (대화에서 범위 3번 · 호스팅 A안(앱에 추가) · 흐름 ① · 데이터/판독 ② 승인)
배경: 전인규 도제 과제 「1주일 안에 후보 20개」(위키 [[도제 상담 1회차 전인규 2026-09-27]]). 네이버 쇼핑은 API 종료(2026-08-01)·확장 차단으로 자동 수집이 안 되므로, **사람이 캡처하고 AI가 판독**하는 도구를 다른 PC에서도 쓸 수 있게 앱에 둔다.

## 목표

1. 네이버 쇼핑 카테고리 캡처(여러 장)를 올리면 상품 목록으로 판독하고 자동 거름망을 칠한다.
2. 후보마다 1688 캡처를 붙이면 원가를 판독하고 **같은 물건인지** 검증한다.
3. 채택한 1688 업체로 강의 공식·실측 공식을 나란히 판정하고, 20개 제출 목록을 뽑는다.

## 비목표

- 네이버·1688 자동 크롤링 (차단된다 — 캡처가 입력이다)
- 판매자 조회수 수집 (캡처에 안 보인다. 리뷰 수를 대리 지표로 쓴다)
- `MIN_SELL_PRICE_KRW`(10,000) 수정 — 다른 화면 영향. 이 화면은 `breakEvenPrice()`로 하한선을 계산한다
- `sourcing-review/formulas.js`(/calc) 교체 — 후속 과제

## 화면 흐름 (`/sourcing/candidates`, PC, 로그인 필요)

### 1. 스캔 — 네이버 캡처 묶음 업로드

- 드래그앤드롭 · 파일 선택 · `Ctrl+V` 붙여넣기. 한 번 올린 묶음 = `sourcing_scans` 1건.
- **전체 페이지 캡처 1장도 받는다** (Chrome DevTools 「Capture full size screenshot」). **브라우저가** ① 아래쪽 빈 영역을 잘라내고 ② 세로 2,576px 단위로 600px씩 겹쳐 조각낸 뒤(JPEG) — 서버가 아니라 브라우저인 이유는 Vercel 요청 본문 4.5MB 상한이다(찜질 원본 PNG 4.5MB). 겹침 600px는 상품 카드 한 칸 높이(약 430px)보다 커야 모든 카드가 어느 조각엔가 온전히 들어간다. 조각 가장자리에서 잘린 카드는 판독하지 않는다. ③ 조각을 순서대로 여러 장 캡처와 같은 파이프라인에 넣는다.
  - 실측(2026-09-27, 냉온/찜질용품): 1985×16384px 중 **상품은 위쪽 약 4,450px(약 50개)만 그려지고 나머지는 흰 빈칸**이었다. 16384는 Chrome 캡처 높이 상한이며, 네이버가 화면 밖 상품을 그리지 않아 생긴 것으로 보인다. 글자는 선명해 판독에는 문제없다.
  - 두 번째 실측(주방용품 > 도마, 1985×6755px): **상한에 걸리지 않고 약 55개가 전부 찍혔다.** 아래쪽 5줄은 상품 사진이 회색 자리표시로 나왔지만 **글자는 온전했다** — 판독에는 사진이 필요 없다. 맨 아래 1~2줄은 글자도 없는 로딩 뼈대다.
  - 🔴 **정렬 바 위의 추천 블록을 순위에서 뺀다.** 도마 캡처 상단에 「○○님을 위한 맞춤 상품」·「매일 필요한 만원 장보기」·「슈퍼신상」이 있었다 — 판매순 목록이 아니라 광고·추천이다. 판독은 **정렬 바(추천순·판매 많은순…) 아래 격자만** 순위로 매기고, 정렬 바에서 굵게 표시된 항목을 정렬 기준으로 읽는다.
  - 로딩 뼈대(판매자·가격 글자가 없는 칸)는 상품으로 세지 않는다.
  - 그래서 빈칸 판정(행 픽셀 분산 ≈ 0이 연속 500px 이상)으로 끝을 자르고, 화면에 「상품 약 N개 인식 — 더 필요하면 스크롤해서 추가 캡처」를 띄운다.
- 첫 장의 **카테고리 경로**(예: 건강/의료용품 > 냉온/찜질용품)와 **정렬 기준**(판매 많은순 등)을 묶음 전체에 적용한다.
- **순위** = 캡처 순서 × 화면 내 위치(행 우선, 좌→우).
- **겹침 제거**: 스크롤 캡처는 줄이 겹친다(실례: 2026-09-27 찜질 캡처에서 들꽃잠 눈찜질팩이 두 장에 찍힘). AI가 한 번에 N장을 보고 1차로 합치고, 코드가 중복 키 `정규화(판매자) + 정규화(상품명) + 판매가`로 2차로 합친다. 합칠 때 순위는 먼저 나온 값을 쓴다.

### 2. 후보 표 — 자동 거름망

열: 순위 · 상품명 · 판매자 · 판매가 · 정가 · 리뷰 수 · 별점 · 배지(공식/우수셀러) · 거름망 · ⭐

| 거름망 | 기준 | 처리 |
|---|---|---|
| 판매가 하한선 | 판매가 < `minViablePrice(calc1688UnitCost(¥5, 소형).effectiveCost, 'small')` = **12,097원** (2026-09-27 앱 상수 기준. 마진율 30% 조건만 쓴 값 · `breakEvenPrice`는 물류비 1.5배 조건까지 넣어 14,813원이라 사전 거름망으로는 너무 세다 · 위키 11,900원과의 차이는 국제배송 추정 883→1,323원, 위키 [[장갑 카테고리 판정과 판매가 하한선 2026-08-23]]) | 🔴 자동 제외 — **접어 두고 되살릴 수 있다** |
| 공식 스토어 | 배지 「공식」 | 🟡 강자 가능성 |
| 전기·의료 | 상품명에 `전기·온열기·의료기기·충전식` 등 | 🟡 인증 확인 필요 |
| 강자 | 리뷰 ≥ 10,000 | 🟡 강자 가능성 |

⭐로 후보를 올린다. 거름망 결과는 저장하지 않고 렌더 때 계산한다(상수 변경을 자동으로 따른다).

### 3. 후보 카드 — 1688 매칭

- ⭐ 후보를 열면 카드. 1688 캡처를 붙인다 — **한 번 올린 묶음 = 업체 1곳**(가격 화면·판매량 화면을 나눠 찍어도 한 업체로 묶이게). 업체를 더 비교하려면 다시 올린다.
- **짝은 사람이 정한다**(캡처를 넣은 카드 = 그 후보). AI는 매칭을 추측하지 않는다.
- AI가 업체마다 뽑는 것: 구간가(수량→위안), 옵션별 가격, 누적 판매량, 판매 단위(`件`·쌍·세트).
- AI가 **같은 물건 판정**: ✅ 같음 / ⚠️ 차이 있음 / ❌ 다른 물건 + 이유 한 줄. 비교 축은 형태·크기·소재·용도·**판매 단위**(실례: 핸들 토시 `件`이 한 짝이면 쿠팡 좌우 세트와 수량이 2배 다르다 — 위키 [[1688 샘플 8종 강의 검토 목록 2026-09-26]]).
- 1688 URL은 캡처에 찍히지 않으므로 **입력칸을 따로** 둔다. 비워도 판정은 되고 제출 목록에 「링크 없음」.
- 업체를 나란히 비교해 **채택** 1개. 채택 시 판정이 붙는다.

### 4. 판정 (채택 업체 기준)

입력: 위안 = 채택 업체의 **최소 주문 구간 단가**(수정 가능) · 판매가 = 네이버 판매가(수정 가능) · 크기 = 소형 기본(극소형/소형/중형 선택).

| 공식 | 식 | 통과 기준 |
|---|---|---|
| 강의 | 착륙원가 = 위안 × 210 × 1.4 · 원가율 = 착륙원가 ÷ 판매가 | **≤ 30% 통과**, ≤ 10% 「최선」 표시 (상담에서 30%까지 허용 — 위키 [[도제 상담 1회차 전인규 2026-09-27]]) |
| 실측 | `calc1688UnitCost` → `marginOf` (로켓그로스 물류비·실효 수수료·간이과세 포함) | 마진율 ≥ 30% **그리고** 마진 ≥ 물류비 × 1.5 |

일 판매량 = 누적 판매량 ÷ 180 (강의 방식. 1688 표시 기간은 미확인이라 참고치로 표시).

⚠️ 실측 공식은 **쿠팡 로켓그로스** 전제다. 판매가는 네이버 캡처 값이므로 화면에 「쿠팡 판매가로 바꿔 보세요」 안내를 둔다.

### 5. 제출 목록

채택까지 끝난 후보를 한 표로: 상품 · 카테고리 · 판매가 · 리뷰 · 1688 링크 · 위안 · 강의 원가율 · 실측 마진/마진율 · 같은 물건 판정 · 메모. 인쇄용 레이아웃(`/sourcing/candidates/print`).

## 데이터 (마이그레이션 1개)

```
sourcing_scans
  id uuid pk, user_id, created_at
  category_path text, sort_label text
  image_paths text[]                 -- Storage 경로 (uuid 포함)
  parse_status  pending|parsing|parsed|failed
  parse_attempts int (≤3), parse_started_at, parse_error text

sourcing_listings
  id uuid pk, scan_id fk, user_id
  rank int, title, seller, price int, list_price int null,
  review_count int null, rating numeric null, badges text[]
  dedup_key text (scan 내 unique)
  number_check text null            -- 할인율 불일치 등 판독 의심
  starred bool, excluded_override bool null   -- 사람이 거름망을 뒤집은 경우
  memo text, size text default 'small', price_override int null

sourcing_offers
  id uuid pk, listing_id fk, user_id
  image_paths text[], url text null
  tiers jsonb        -- [{minQty, cny}]
  options jsonb      -- [{name, cny}]
  sold_count int null, sale_unit text null
  match_verdict same|diff|different, match_reason text
  cny_override numeric null, adopted bool (listing당 최대 1 — partial unique index)
  parse_status/attempts/error (scans와 같음)
```

- RLS: `user_id = auth.uid()`. 이미지는 영수증과 같은 버킷 규칙(uuid 경로)이고 **판독 후에도 지우지 않는다** — 오독 대조용.
- 판정·거름망은 저장하지 않는다(파생값).

## 판독 (영수증 `src/lib/receipt/` 패턴 재사용)

| 단계 | 재사용 | 신규 |
|---|---|---|
| 축소 | `receipt/downscale.ts` (2,576px 상한 — 더 줄이면 숫자 오독 증가) | — |
| 호출 | `lib/ai/claude-vision` 클라이언트, 영수증과 같은 모델 | `lib/sourcing-candidates/extract-naver.ts` · `extract-1688.ts` (tool 스키마로 구조화 출력) |
| 검증 | `receipt/verify.ts` 방식 | `verify.ts`: 판매가 ≤ 정가 · 표시 할인율 ≈ 1 − 판매가/정가(±1%p) · 구간가는 수량 증가에 따라 비증가 |
| 상태 | `receipt/draft-status.ts` (3회 후 failed, 10분 회수) | — |

- 화면 종류 판별을 먼저 한다 — 네이버 자리에 1688 캡처(또는 반대)를 올리면 거부한다.
- 묶음 일부만 실패하면 성공분은 저장하고 실패한 장만 다시 올리게 한다.
- 모든 숫자 칸은 표에서 수정 가능. **사람 수정값이 AI 값보다 우선**한다(`*_override`).

## 계산 모듈

- 신규 `src/lib/sourcing/lecture-formula.ts` — 강의 공식의 **원본**. 상수 `LECTURE_RATE=210`, `LECTURE_MULTIPLIER=1.4`, `LECTURE_COST_RATIO_PASS=0.30`, `LECTURE_COST_RATIO_BEST=0.10`. 출처 주석에 위키 문서명.
- 실측은 기존 `cost-1688.ts`·`coupang-price.ts`를 그대로 호출한다. 사본을 만들지 않는다.
- 신규 `src/lib/sourcing-candidates/filters.ts` — 거름망 4종, `dedup.ts` — 중복 키.

## 열린 질문

- 네이버 상세 링크를 받을 방법 — 캡처에는 없다. 지금은 선택 입력칸.
- 제출 목록을 위키(`20-wiki/outputs/`)로 내보낼지 — 첫 20개를 써본 뒤 정한다.
