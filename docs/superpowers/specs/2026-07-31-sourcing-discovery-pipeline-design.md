# 소싱 발굴 파이프라인 설계

- 작성일: 2026-07-31
- 브랜치: `feat-sourcing-shortlist`
- 선행 문서: `2026-07-31-sourcing-shortlist-design.md`

## 배경

### 목표는 2026-12 월매출 3,000만원이다

| 항목 | 금액 |
|---|---:|
| 목표 (2026-12 월매출) | 3,000만원 |
| 코스트코 라인 (추산) | 1,000만원 |
| **1688 신규로 필요** | **2,000만원** |

극세사 타월급 히트(월 483만원) 환산으로 **4.1개**가 필요하다. 지금까지 활성 상품 46개에서 나온 히트가 3개이므로 히트율은 6.5%이고, 4개를 만들려면 **약 62종을 테스트**해야 한다.

해운 리드타임 30일에 검증 4주를 더하면 사이클이 약 10주다. 5개월에 2바퀴이므로 **회당 31종을 동시 진행**해야 하며, **8월 안에 1차 발주**가 나가야 12월 매출로 잡힌다.

### 발굴 파이프라인이 끊겨 있다

부품은 대부분 있는데 연결되지 않았다.

| 단계 | 모듈 | 상태 |
|---|---|---|
| 트렌드 시드 수집 | `trend-discovery.ts` | 크론 동작. 매일 10개가 `trend_seeds`에 쌓임 |
| 시드 스코어링 | `seed-scoring.ts` | **테스트에서만 호출.** 프로덕션 연결 없음 |
| 도매꾹·1688 매칭 | `keyword-pipeline.ts` | **텔레그램 웹훅으로만 실행.** `/api/sourcing/agent/run`은 `vercel.json`에 등록되어 있으나 **파일이 없어 매번 404** |
| 손익 판정 | `shortlist-verify.ts` | 동작. 단 **후보를 손으로 입력**해야 함 |

매일 시드 10개가 쌓이는데 볼 화면이 없고, 등급을 매기는 코드는 아무도 호출하지 않는다. 소싱리스트는 **총 0개 후보** 상태다.

### 시드 프롬프트가 자체 규제 필터에 걸리는 키워드를 만든다

`trend-discovery.ts`가 "좋은 예시"로 제시한 4개를 `lib/sourcing/legal/`에 넣으면 전부 차단된다.

| 프롬프트의 좋은 예시 | 판정 |
|---|---|
| 강아지 영양제 | 건기식 — `category-filter` 위험 |
| 캠핑 랜턴 | 전기용품 KC — `kc-check` |
| 에어프라이어 틀 | 식품용기 — 차단 실적 169건 |
| 고양이 장난감 | 장난감 — 차단 실적 466건 |

프롬프트가 예시로 드는 "휴대용 선풍기"는 실제 차단 상위 항목이다(420건).

### 원가 계산에 결함 3건이 있다

| # | 위치 | 내용 |
|---|---|---|
| 1 | `coupang-price.ts` | `COMMISSION_RATE = 0.108`이 VAT 미반영. `lib/tax.ts`의 `effectiveFeeRate()`(11.88%)를 쓰지 않아 **마진이 판매가의 약 1.1%p 과대평가** |
| 2 | `margin-1688.ts` | 관세 과세가격에 **운임이 빠져 있다.** 정확한 식은 `과세가격 = 상품가 + 운임`인데 상품가만 쓴다. 소량 발주에서 3.3% 과소 계상 |
| 3 | `margin-1688.ts` | 관세율이 단일 입력값. **의류 13% / 장갑·가방·액세서리 8%** 등 품목별 차등이 반영되지 않는다 |

## 목표

1. 매일 쌓이는 트렌드 시드를 화면에서 보고 골라서 분석한다
2. 분석 결과가 소싱리스트에 자동으로 쌓인다
3. 1688 상품 페이지를 붙여넣으면 원가가 자동 계산된다
4. 검증 후 스케일업·중단·세일 매입을 한 화면에서 판단한다

## 비목표

- **1688 자동 매칭을 하지 않는다.** 사용자가 1688에서 직접 유사품을 찾아 붙여넣는다. `china-matcher.ts`·`image-similarity.ts`는 남기되 파이프라인에서 호출하지 않는다
- **시드 스코어링(S~D 등급)을 이번에 붙이지 않는다.** 입력에 검색량·경쟁사 수·리뷰 수가 필요한데, 어떤 시드가 실제로 좋았는지 데이터가 없는 상태에서 등급을 매기면 근거 없는 점수가 된다. 실행 이력이 쌓인 뒤 2차로 다룬다
- **쿠팡 광고를 자동 집행하지 않는다.** "이 상품에 얼마를 태워라"를 안내하는 데까지만 한다

## 전체 구조

### 탭 재구성

```
현재:  소싱리스트 | 코스트코 | 봇결과 | 메모
변경:  발굴 | 소싱리스트 | 액션 | 코스트코 | 메모
```

| 탭 | 역할 | 변경 |
|---|---|---|
| 발굴 | 트렌드 시드 목록 + 키워드 직접 입력 + 실행 | 봇결과 탭을 개편. 조회 전용 → 실행 가능 |
| 소싱리스트 | 발굴 결과 자동 적재 + 1688 원가 인라인 입력 | 수동 입력도 유지 |
| 액션 | 스케일업 · 중단 · 검증미실시 · 코스트코 세일 · 1688 발주 | 신설 |
| 코스트코 | 기존 유지 + 감시 대상 확대 | 거의 그대로 |
| 메모 | 그대로 | — |

### 데이터 흐름

```
[발굴]
 trend_seeds (Gemini 크론, 매일 10개)  ─┐
 수동 키워드 입력 ──────────────────────┴→ 선택한 시드만 파이프라인 실행
                                            ↓
      ① 도매꾹 검색 (키워드당 10건)          도매꾹 API 1회
      ② 규제 필터 (legal/ 6개 레이어)        로컬
      ③ 배송비 개당 환산                     로컬
      ④ 쿠팡 시세 추정 (p25)                 네이버 API 최대 4회/상품
      ⑤ 손익분기 판정                        로컬
                                            ↓
[소싱리스트]  pass 자동 적재 · unknown 수동 적재 · fail/dead 기록만
                                            ↓ 사용자가 1688에서 유사품 검색 (수동)
              1688 페이지 붙여넣기 → 원가 자동 계산 → 사입 확정
                                            ↓
[액션]        1688 발주 (5종 50~80개 묶음) → 실비 배분 → 원가 확정
                                            ↓ 입고 · 광고 5~10만원 · 4주
              광고비 5,000원 미만? ─ 예 → 검증 미실시 "광고를 태워라"
                                    └ 아니오 → 월 20개 이상? ─ 예 → 스케일업
                                                             └ 아니오 → 중단
              코스트코 임계가 하회 → 대량 매입
```

## 발굴

### 시드는 골라서 실행한다

전량 자동 투입하지 않는다. 하루 10시드 × 후보 5개 = 50개가 매일 쌓이면 5개월에 7,500개가 되어 리스트가 오염되고 API 비용만 나간다.

체크한 시드만 분석 버튼으로 파이프라인에 태운다. 체크하지 않은 시드는 API를 한 번도 부르지 않는다.

### 시드 프롬프트 교정

| 항목 | 현재 | 변경 |
|---|---|---|
| 금지 카테고리 | "포화 대형 카테고리 제외" | **전기·충전·배터리 / 아동·유아·장난감 / 식품·건기식·식품용기 / 화장품·세제·위생용품** 명시 |
| 예시 카테고리 | 생활용품·주방·청소·건강식품·반려동물·캠핑·뷰티 | **골프·낚시·등산·아웃도어 액세서리·방한보온·차량용품** (주방·건강식품·뷰티 제거) |
| 단가 | 없음 | **개당 예상 판매가 1만원 이상, 2만원 이상 우대** |
| SKU 분기 | 없음 | **색상·사이즈 옵션 3개 이하. 의류는 프리사이즈·밴딩 우선** |
| 시즌 | 없음 | **오늘 기준 2~4개월 뒤 시즌** |

### 통과 기준

| 조건 | 값 | 근거 |
|---|---|---|
| 규제 | `legal_status = safe` | `lib/sourcing/legal/` 6개 레이어 (이미 작동) |
| 판매가 | 1만원 이상 | 목표 역산 |
| 마진율 | 30% 이상 | 광고 손익분기 ROAS 333% |
| 개당 마진 ÷ 물류비 | 1.5배 이상 | 요율 인상 완충 |
| SKU 분기 | 3 이하 | 필통 실측 — 3색 중 민트 0개 판매 |

정렬은 **예상 판매가 내림차순**이다. 시간이 부족해 상위 몇 개만 실행하더라도 목표에 가까운 것부터 처리된다.

### 소싱리스트 적재 규칙

| 판정 | 처리 |
|---|---|
| `pass` | 소싱리스트에 자동 적재 |
| `unknown` (쿠팡 표본 3건 미만) | 발굴 탭에 남김. 버튼으로 수동 적재 |
| `fail` · `dead` | 발굴 탭에만 표시. 적재하지 않음 |

`unknown`을 `fail`로 뭉치지 않는다. 표본이 얇아 모르는 것과 마진이 안 나오는 것은 다르다. `fail`·`dead`도 화면에서 지우지 않는다 — 왜 탈락했는지가 기록이고, 없으면 같은 후보를 다시 뽑는다.

## 원가 계산

### 국제배송 — 더싼배대지

요율표(항공 기준, 2026-07-31 확인):

| 무게 | 배송비 | kg당 환산 |
|---:|---:|---:|
| 0.5kg | 4,180원 | 8,360원 |
| 1kg | 4,580원 | 4,580원 |
| 10kg | 17,390원 | 1,739원 |
| 100kg | 140,790원 | 1,408원 |

1~20kg 구간 근사식 (10kg에서 오차 3원):

```
배송비 ≈ 4,580 + (kg − 1) × 1,423
```

**부피무게가 의류를 지배한다.**

```
부피무게 = 가로 × 세로 × 높이 ÷ 6000
과금무게 = max(실무게, 부피무게)
```

모자는 실무게 0.10kg인데 25×20×12cm면 부피무게 1.00kg으로 **10배**가 된다.

**건당 고정비가 배송비보다 크다.**

| 항목 | 금액 |
|---|---:|
| 관세사 수임료 (사업자) | 22,000원 |
| 목록통관 창고료 (2kg 미만) | 750원 |

| 발주 규모 | 배송비 | 고정비 | 개당 부대비 |
|---:|---:|---:|---:|
| 10개 (1kg) | 4,580원 | 22,000원 | **2,658원** |
| 82개 (8.3kg) | 15,572원 | 22,000원 | 458원 |
| 300개 (30kg) | 45,847원 | 22,000원 | 226원 |

소량 단품 발주는 성립하지 않는다. **5종 50~80개 묶음 발주가 기본 단위**다.

> **해운 요율은 미확인이다.** 사용자는 해운을 쓰지만 업체 페이지에 해운 요율표가 없다. 항공 요율을 상한으로 두고 보수적으로 계산하며, 요율은 설정으로 분리해 첫 청구서로 교정한다. 추정으로 채우지 않는다.

### 관세·부가세

계산식 (업체 안내 기준):

```
과세가격 = 상품가 + 과세운임
관세     = 과세가격 × 품목별 관세율
부가세   = (과세가격 + 관세) × 0.1
개당원가 = 과세가격 + 관세 + 부가세
```

품목별 관세율:

| 품목 | 관세율 |
|---|---:|
| 의류·수영복·속옷 | **13%** |
| 신발류 | 13% |
| 스카프·숄·넥타이·장갑 | 8% |
| 가방·핸드백 | 8% |
| 액세서리 | 8% |
| 화장품·향수 | 8% |

부가세는 전 품목 10%다. **간이과세자라 매입세액 공제를 받지 못하므로 수입 부가세가 그대로 원가가 된다.**

실제 가산율 (상품가 10,000원, 5종 65개 묶음 발주 기준):

| 항목 | 장갑 (8%) | 의류 (13%) |
|---|---:|---:|
| 상품가 | 10,000원 | 10,000원 |
| 개당 운임 | 600원 | 600원 |
| 관세 | 848원 | 1,378원 |
| 수입 부가세 | 1,145원 | 1,198원 |
| **개당 원가** | **12,593원** | **13,176원** |
| 상품가 대비 | +25.9% | +31.8% |

**1688 가격에 26~32%를 더해야 실제 원가다.**

### 붙여넣기 파싱

1688 상품 페이지를 드래그해 붙여넣으면 중국어와 숫자가 섞인 텍스트가 들어온다. 정규식은 페이지 구조가 바뀔 때마다 깨지므로 **기존 `/api/ai/extract-product-info`를 재사용**한다.

| 필드 | 출처 |
|---|---|
| 박스가 (¥) · 입수 · 상품명 · 치수 | 붙여넣기에서 AI 추출 |
| 환율 | 자동 조회 (캐시) |
| 관세율 | 카테고리 매핑값 (수정 가능) |
| 개당 국제배송 | 발주 구성에서 계산 (추정 → 실비 교정) |
| 물류비 | 사이즈 선택 → `rg-fees.ts` |

파싱 실패 시 **수동 입력 폼으로 폴백**한다. 붙여넣기는 편의지 필수 경로가 아니다.

### 발주 실비 배분

발주가 확정되면 **배송비와 건당 고정비를 모두 과금무게 비례로 배분**해 원가를 확정한다.

```
배분 대상 = 실제 배송비 청구액 + 관세사 수임료(22,000) + 창고료

상품          수량  개당무게  총무게   비중     배분액    개당 부대비
방한 터치장갑  52    0.10kg   5.20kg   62.7%   23,160원    445원
넥워머         20    0.08kg   1.60kg   19.3%    7,128원    356원
골프 파우치    10    0.15kg   1.50kg   18.1%    6,680원    668원
──────────────────────────────────────────────────────────────────
합계          82             8.30kg  100.0%   36,968원
              (배송비 14,968 + 고정비 22,000)
```

**관세는 배분하지 않는다.** 품목별 세율이 다르므로 각 상품의 `과세가격 × 자기 세율`로 개별 계산한다. 이때 과세운임은 위 표의 개당 부대비 중 **배송비 몫만** 쓴다 — 관세사 수임료는 과세운임이 아니다.

추정 무게와 실제 무게의 차이가 쌓이면 카테고리 기본 무게가 정확해진다. 추정으로 판정하고 실비로 장부를 맞추는 구조다.

## 액션

### 판정을 3분기로 나눈다

"4주 지났는데 안 팔림 → 중단"으로 만들면 안 된다. 실패로 분류된 상품들의 평균 광고비가 266원이었고, 성공 상품은 13,349원이었다. **팔리지 않는 상품이 아니라 팔아보지 않은 상품이었다.**

```
광고비 5,000원 미만?
  ├─ 예 → 검증 미실시   "광고를 태워라"
  └─ 아니오
        └─ 월 환산 20개 이상?
              ├─ 예   → 스케일업  "재고를 늘려라"
              └─ 아니오 → 중단    "정리해라"
```

### 재고 상태를 함께 본다

| 재고 | 판매 | 판정 |
|---|---|---|
| 충분 | 20개 이상 | 스케일업 |
| 충분 | 미달 | 중단 |
| 품절·부족 | 무관 | **재고부터 채움 — 판단 보류** |

필통이 월 6개인 것은 수요가 아니라 재고 한계다(핑크·화이트 재고 0). 이를 "미달 → 중단"으로 판정하면 틀린다.

### 재발주 시점

```
재발주 경보 = 잔여재고 ÷ 일평균판매 ≤ 리드타임(30일) + 안전재고(14일)
```

해운 리드타임이 30일이므로 재고가 1개월치 남았을 때 이미 발주했어야 한다.

### 스케일업 규모

| 단계 | 재고 | 조건 |
|---|---:|---|
| 검증 | 10개 | 신규 진입 |
| 1차 확대 | 2개월치 (월판매 × 2) | 월 20개 돌파 |
| 2차 확대 | 2개월치 재산정 | 월 100개 돌파 |

2개월치인 이유는 리드타임이다. 주문·배송 중 품절되면 랭킹이 떨어진다.

### 코스트코 세일

기존 `costco_price_watches`를 확장한다. 감시 대상을 상품별 임계가로 등록하고, 임계가를 밑돌면 알린다. 재알림은 **처음 하회할 때와 더 싸질 때만** 보낸다.

## 데이터 모델

| 테이블 | 상태 | 용도 |
|---|---|---|
| `trend_seeds` | 기존 | 시드 목록 |
| `keyword_requests` / `keyword_results` | 기존 | 발굴 실행 이력 |
| `shortlist` | **컬럼 추가** | 아래 참조 |
| `intl_orders` | **신규** | 발주 헤더 (배송사·방식·실청구액·고정비) |
| `intl_order_items` | **신규** | 발주 품목 + 배분 결과 |
| `costco_price_watches` | 기존 | 세일 감시 |
| `sale_records` · `product_costs` | 기존 | 액션 판정 입력 |

`shortlist` 추가 컬럼:

```
buy_price_rmb      1688 박스가
pack_qty           입수
weight_kg          실무게
dims_cm            가로/세로/높이
tariff_rate        관세율 (카테고리 매핑값, 수정 가능)
unit_cost_krw      확정 개당 원가
```

**액션 판정은 테이블을 만들지 않는다.** `sale_records` + 재고 + 광고비로 매번 계산한다. 상태를 저장하면 실제와 어긋날 때 고치기 어렵다.

## 모듈 구성

```
lib/sourcing/intl-shipping.ts   요율표 → 배송비, 부피무게, 발주 배분
lib/sourcing/tariff.ts          카테고리 → 관세율, 과세가격 → 관세·부가세
lib/sourcing/paste-1688.ts      붙여넣기 → 구조화 (AI 추출 래핑)
```

셋 다 순수 함수로 만들어 단위 테스트를 건다. 소싱리스트 인라인 입력과 마진 계산기가 같은 모듈을 쓴다.

## 에러 처리

크론 4개가 405로 3개월간 죽어 있었는데 아무도 몰랐다. **수집 계열 기능은 마지막 성공 시각을 눈에 보이는 곳에 두어야 한다.**

| 실패 지점 | 처리 |
|---|---|
| 시드 크론 | **발굴 탭 상단에 마지막 수집 시각 표시.** 24시간 초과 시 경고 배지 |
| 도매꾹 API | 부분 결과 저장 + 실패 건수 표시. 전체 실패로 처리하지 않음 |
| 네이버 API 한도 | 백오프 후 `unknown` 판정 |
| 쿠팡 표본 3건 미만 | `unknown` (기존 규칙 유지) |
| AI 붙여넣기 파싱 실패 | 수동 입력 폼으로 폴백 |
| 발주 배분 시 무게 누락 | 카테고리 기본 무게 × 1.5로 보수 계산 + 추정값 표시 |

## 구현 순서

**8월 발주가 기준점이다.** 해운 사이클 10주를 고려하면 8월 안에 1차 30종이 나가야 12월 매출에 잡힌다.

| 단계 | 항목 | 시점 |
|---|---|---|
| 1 | 시드 프롬프트 교정 · `/api/sourcing/agent/run` 라우트 · 발굴 탭 · 소싱리스트 자동 적재 | 8월 1주 |
| 1 | 버그 3건 — `coupang-price` VAT · `margin-1688` 과세운임 · 관세율 카테고리 매핑 | 같이 |
| 2 | 1688 붙여넣기 · 소싱리스트 인라인 마진 · 국제배송 설정 화면 | 8월 2주 |
| 3 | 발주 화면 + 실비 배분 | 8월 3주 (첫 발주 직전) |
| 4 | 액션 탭 — 스케일업 · 중단 · 검증미실시 · 코스트코 | 9월 (재고 도착 후) |

버그 3건을 1단계에 넣는 이유는 이것들이 마진 판정을 왜곡해 **잘못된 후보를 통과시키기 때문**이다. 발굴을 먼저 돌리는 이상 판정이 정확해야 한다.

## 미해결 사항

- **해운 요율표 미확인.** 업체 페이지에 없다. 항공 요율을 상한으로 쓰고 첫 청구서로 교정한다
- **해운 리드타임 30일은 가정이다.** 실제 소요를 첫 발주에서 측정해야 한다
- **히트율 6.5%는 46개 표본 추정치다.** 검증을 제대로 한 뒤의 히트율은 다를 수 있다
- **월 20개 기준의 근거가 얇다.** 1688 직소싱 성공작인 필통이 월 6개(품절 상태 측정)라 실제 달성 가능 수준이 미검증이다
- **카테고리별 기본 무게·치수 테이블이 없다.** 첫 발주 실측으로 채워야 한다
