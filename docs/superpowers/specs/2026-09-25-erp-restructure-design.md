## 목표

1. 스마트셀러스튜디오를 **매일 여는 ERP형 운영 콘솔**로 재구성한다.
2. 재고·주문·원가의 **기초 장부**(상품마스터 SKU · 재고 원장 · 주문↔상품 매핑 · 작업 로그)를 먼저 세운다. 화면은 그 위에 얹는다.
3. 판매 채널 다변화와 자사 제품(직접 발송 증가)에 대비한다. 새 채널은 **어댑터 하나**로 붙인다.

**성공 기준**: Wing·스마트스토어센터를 열어야만 할 수 있는 일이 하루 0건.

- 메뉴 정의는 `src/lib/erp-menu.ts` **한 곳**. 사이드바·탭 이름·브레드크럼을 여기서 만든다. 기존 `nav-items.tsx`와 `EXTRA_LABEL_RULES`를 대체한다.
- **URL은 기존 경로를 유지**하고 메뉴 코드만 붙인다.
- 사용 빈도 근거(최근 30일 DB 기록): `sale_records` 841 · 입고·원가(영수증 16, `cost_entries` 53, `costco_item_map` 24) · `product_cost_channels` 70. 등록·상세 화면은 CLI로 대체돼 `coupang_drafts` 05-28, `detail_page_drafts` 08-05가 마지막이다. DB는 쓰기만 재므로 조회 전용 화면의 빈도는 이 근거로 보이지 않는다.

## 화면 틀

- 레이아웃: 상단 바(통합검색 · 라벨 인쇄 · 작업로그 실패 표시 · 알림) + 좌측 코드 트리 + 탭(기존 `TabBar`) + 작업 영역 + **우측 상세 패널**(팝업 대신 — 그리드를 가리지 않는다).
- 목록 화면 공통 틀: **조회조건 패널 → 결과 툴바(건수·일괄 버튼·엑셀↓·컬럼) → 그리드 → 상태 바**.
- 그리드: TanStack Table(headless) + 가상 스크롤 · 컬럼 고정/리사이즈 · 체크박스 다중선택 · 합계 행 · 엑셀 내보내기 · 컬럼 설정 저장 · 인라인 편집.
- 스타일: `src/lib/design-tokens.ts`의 ERP 토큰 `E`를 CSS 변수 + Tailwind 테마로 옮긴다. 새 컴포넌트는 클래스로 쓰고, 기존 인라인 `style`(약 4,989곳)은 화면을 옮길 때 바꾼다. `src/components/orders/erp-ui.tsx`가 출발점이다.
- 데이터 로딩: 목록 API 규격(필터·정렬·페이지)을 하나로 정하고 **TanStack Query**로 캐시한다. 페이지 나누기는 서버에서 한다.
- 제외: 다중 사용자 권한 · 테마 전환 · 단축키 체계 · 즐겨찾기 편집 · 엑셀 업로드 왕복(그 역할은 Claude CLI + 인라인 편집이 맡는다). `/m/*` 모바일 화면은 유지.

## 데이터 구조 (`erp` 스키마)

```
skus ──┬── sku_components     세트 → 구성품 × 수량
       └── purchase_units      매입단위 → 판매단위 × 소분배수   (costco_item_map 흡수)
skus ◄── channel_listings      채널상품·옵션 ↔ SKU × 배수       (product_cost_channels + stock_sync_links 통합)
channel_listings ◄── order_lines ── orders                     표준상태 · 원래 채널 상태 · 송장 · 출고주체(rg/self)
skus ◄── stock_ledger          SKU · 위치(self/rg) · ±수량 · 종류 · lot 단가 · 원천(ref) · 역전표 연결 · 멱등키
job_runs                        작업 · 시작/종료 · 결과 · 처리 건수 · 오류(PII 마스킹)
sync_cursors                    채널별 마지막 수집 시각
```

### 원칙

| 원칙 | 내용 |
|---|---|
| 재고는 저장하지 않고 계산 | 재고 = 원장 합계. 할당 = 출고대기 주문 수량. `current_stock` 류 컬럼을 두지 않는다 |
| 위치별 가용 | 직접발송 채널 전송값 = 자체 재고 − 할당 − 안전재고. **RG 재고는 절대 합산하지 않는다**(RG는 쿠팡 RG 주문만) |
| 원가와 재고는 한 원장 | 입고 전표가 lot 단가를 갖고, 판매 차감 전표가 FIFO로 lot을 소진한다 |
| 고치지 않고 되돌린다 | 전표는 수정·삭제하지 않는다. 역전표로 상쇄한다 |
| 중복 불가 | `(channel, external_line_id)` 유니크 · 전표 멱등키 |
| 세트 판매 | 세트 SKU가 팔리면 구성품 재고를 차감한다 |
| 소분 입고 | 매입 1단위 입고 = 판매단위 × 소분배수로 원장에 넣는다 |

### 주문 표준 상태

`신규 → 발주확인 → 출고대기(할당) → 로지아이 전달 → 송장반영(차감) → 배송완료`, 분기 `취소 · 반품 · 교환`.
- 원래 채널 상태 문자열은 `status_raw`로 보존한다.
- **「로지아이 전달 후 송장 미반영 6시간 초과」**를 별도로 감시한다(A11 카드).
- RG 주문은 쿠팡 출고로 바로 차감한다.

### 채널 어댑터 인터페이스

`fetchOrders(cursor)` · `updateStatus(line, status)` · `fetchInvoiceState(line)` · `pushStock(listing, qty)` · `fetchListings()`. 채널별 코드는 이 뒤에 숨긴다. H11에 채널별 지원 매트릭스를 표시한다.

**쓰기 주체는 하나.** 로지아이가 지원하는 채널(쿠팡·스마트스토어 등)의 발주확인·송장은 로지아이가 하고, ERP는 읽기만 한다. ERP가 채널에 쓰는 것은 로지아이 미지원 채널(토스 등)의 상태·송장과 재고 전송뿐이다. `updateStatus`는 채널 설정에서 켜고 끈다.

## 아키텍처 결정

| # | 결정 | 근거 |
|---|---|---|
| 1 | 스케줄러를 **Supabase `pg_cron` + `pg_net`**으로 옮긴다 | `stock-sync.yml`(`0 */3 * * *`)의 최근 16회 실제 간격이 5~6시간이었다(20~58분 지연, 예약의 절반가량 누락). 두 확장은 설치 가능·미설치 상태 |
| 2 | 채널 쓰기는 한 주체만 | 위 어댑터 절 |
| 3 | 기존 품절 동기화(Wing 품절 → 네이버·토스)와 원장 기반 전송을 **동시에 돌리지 않는다** | 전환일에 끄고, 며칠은 기록만 하는 모드로 값을 대조한다 |
| 4 | 잡마다 Postgres advisory lock · 멱등키 · `sync_cursors` | 겹친 실행의 이중 할당과 누락 구간 방지 |
| 5 | 미사용 소싱 cron 정지(코스트코 가격·세일만 유지) | Vercel cron 13개 중 8개가 소싱. DB 427MB 중 최대 테이블이 `inventory_snapshots` 54만·`sourcing_items` 45만 행 |
| 6 | DB 분리 — 투자콕 50개 테이블(4.3MB)을 새 무료 조직 Supabase로 통째 이전 | 2026-08 Render→Supabase 이전 때 셀러 DB로 함께 들어왔다. 셀러 앱 코드는 이 50개를 **한 번도 참조하지 않는다**(셀러 인증은 `auth_users`). Render `investcock-api`가 **지금도 기록 중**(주간 스크리너 09-18 ok · `watch_alerts` 30일 104건)이라 삭제가 아니라 이전이다. `kis_tokens`(증권 토큰)가 셀러 앱 service role 범위에서 빠진다. Pro 조직에 프로젝트를 더하면 컴퓨트 비용이 추가되므로 조직을 따로 둔다(생성 전 요금 페이지 확인) |
| 7 | 프록시 헬스 감시 | 쿠팡·토스 호출은 Vultr 고정 IP 프록시 하나를 거친다. 연속 실패 시 텔레그램 경보 |
| 8 | 목록 API 규격 + TanStack Query | 화면 틀 절 |
| 9 | 로그 PII 마스킹 | 데이터 구조 절 |
| 10 | 대조 보고서를 단계 관문으로 | 아래 검증 절 |

유지: 133개 테이블 전부 RLS on, 서버는 service role(단일 사용자라 충분). 재고 합계 계산 성능은 현재 규모에서 문제없고, 느려지면 월 마감 스냅샷을 더한다.

- **대조 보고서 = 단계 관문**: 매핑 점검(1-1) · RG 재고 일치(1-2) · 주문 건수 일치(1-3) · 기록 모드 과판매 0건(1-4).
- **playwright**: ERP 틀과 핵심 화면 스모크.
