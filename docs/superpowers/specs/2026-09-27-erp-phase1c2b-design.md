# ERP 1-C2b — 미연결 대기열 · 쿠폰 · 당근 · RG 입고 자동 설계

> **TL;DR** 1-C2a가 미룬 네 가지를 한 계획서·PR 4개로 순서대로 붙인다. ① 미연결 주문을 화면에서 SKU에 연결 ② 판매자 부담 즉시할인을 주문 줄·옛 장부에 기록 ③ 당근 직거래를 휴대폰·PC에서 입력해 차감·매출 기록 ④ RG 실재고를 매일 대조해 입고 완료만 자동으로 옮기고 나머지는 알린다. ④는 판매 차감이 켜진 뒤(1-C2a 게이트 ②)라야 판정이 맞다.

- 작성: 2026-09-27 · 상위: `2026-09-25-erp-restructure-design.md` · 선행: 1-C2a(PR #24~#30, 15분 수집 가동, 차감 스위치 꺼짐)
- 결정 기록: `2026-09-27-erp-phase1c2b-decisions.md`

## ① 미연결 주문 대기열

**화면:** `/erp/stock` 수집 현황 패널의 「미연결 N」 → 대기열 창. 미귀속 줄을 `(채널, 상품번호, 옵션 키)`로 묶어 상품명 · 줄 수 · 수량 · 원인(`no_listing` · `option_unmatched` · `any_of` · `no_sku_link`) · 첫·마지막 결제일을 보인다.

| 연결 방법 | 쓰는 때 | 동작 |
|---|---|---|
| **리스팅으로 연결**(기본) | 새 상품번호·옵션 | SKU 검색·선택 + 배수(기본 1) → `channel_listings`(origin `manual`) + `listing_skus` 생성. 이후 주문도 자동 연결 |
| **이 주문만 연결** | `any_of` 등 리스팅 하나가 SKU 여럿 | 그 줄의 `manual_sku_id`에 적는다. 연결 판정기는 `manual_sku_id`를 먼저 본다 — 다음 수집 upsert가 덮지 않는다 |

- 연결 뒤 **채널을 다시 부르지 않고 저장된 줄로 다시 판정** → 옛 장부 기록 → 스위치가 켜져 있으면 차감. 1-C2a의 `reevaluateUnknownLines`와 같은 방식의 「미귀속 재판정」 함수를 둔다.
- 같은 `(채널, 상품번호, 옵션 키)` 리스팅이 이미 있으면 만들지 않고 알린다(유니크 제약이 이미 있다).
- 잘못 연결 → 대기열 창의 「최근 연결」 목록(이 화면에서 만든 `manual` 리스팅·`manual_sku_id`)에서 「해제」: 리스팅 비활성화 또는 `manual_sku_id` 비우기 → 해당 줄 재판정으로 다시 미귀속. 🔵 **이미 뺀 재고는 해제만으로는 되돌리지 않는다** — 1-C2a 판정표가 「팔림인데 연결만 사라진 줄은 판매가 유효하다」로 뺀 것을 둔다. **올바른 SKU로 다시 연결하면** 판정표가 역전표 + 새 차감으로 옮긴다(작성 중 코드 확인으로 정정). `draft` 리스팅은 이 화면에서 해제하지 않는다.
- **데이터:** `erp.order_lines.manual_sku_id bigint null references erp.skus`.

## ② 쿠폰 할인

**원칙:** `amount`(판매가 × 수량)는 그대로, 판매자 부담 할인을 `discount_amount`로 따로 둔다. 실매출 = `amount − discount_amount`.

| 채널 | 출처 |
|---|---|
| 쿠팡 판매자배송 · RG | 주문번호별 즉시할인 쿠폰 조회 `getOrderImmediateDiscount`(fms, 주문당 1회). 발주서 `discountPrice`와의 관계는 첫 작업에서 실측 대조 |
| 네이버 | 상품주문의 판매자 부담 할인 칸(`sellerBurdenDiscountAmount` 계열 — 2026-09-27 응답 칸 목록에 있음) |
| 토스 | `originPrice`·`price` — 부담 주체를 문서·실측으로 확인 |

- 🔴 **첫 작업 = 채널별 운영 응답 실측**으로 할인 칸 이름·의미를 확정하고 그 응답으로 픽스처를 만든다. 1-C2a에서 추정한 칸 이름(`optionCode`)으로 만든 픽스처가 통과한 채 운영에서 틀렸다. 기준값: 극세사 타월 RG 옐로우 판매가 14,100 · 쿠폰 840 · 최종 13,260(2026-09-25 Wing).
- 쿠팡 쿠폰은 **줄마다 한 번** 조회하고 `discount_checked_at`을 남긴다. 수집 1회당 조회 상한 60건(나머지는 다음 수집). 조회 실패는 수집을 막지 않고 다음에 다시.
- 한 주문 여러 줄: 응답에 상품별 금액이 있으면 그대로, 없으면 `amount` 비율로 나눈다(원 단위 반올림, 나머지는 마지막 줄).
- **옛 장부:** `sale_records.coupon_discount`를 같은 값으로. 기존 수익 화면이 이 칸을 빼는 방식을 계획 단계에서 코드로 확인해 이중 차감을 막는다. 9월 보충분은 보충 실행으로 다시 채운다.
- 다운로드 쿠폰은 API로 알 수 없어 빼지 않는다(정책 있는 상품은 극세사 타월뿐, 최대 1,000원).
- **데이터:** `erp.order_lines.discount_amount int not null default 0 · discount_source text null · discount_checked_at timestamptz null`.

## ③ 당근 수동 판매

- **입력:** 휴대폰 `/m/stock` 「당근 판매」 탭 · PC 재고현황 「당근 판매」 버튼. 같은 API `POST /api/erp/sales/karrot` — SKU · 수량 · 금액(합계) · 날짜(기본 오늘 KST) · 메모 · `requestId`(멱등). 최근 당근 판매 목록 + 「되돌리기」.
- **저장:** `erp.orders` 1건 + `erp.order_lines` 1줄, 채널 `karrot`, 외부 번호는 `karrot-<requestId>`, 상태 `paid`, `manual_sku_id`로 SKU 확정. 이후는 다른 채널과 같은 흐름 — 차감은 스위치를 따르고(위치 `self`), 옛 장부 `sale_records` 채널 `karrot`.
- 수집기·사라짐 판정은 `karrot`을 건드리지 않는다(어댑터 없음).
- **재고 초과 입력 차단:** 저장 전 현재 집 재고를 보이고, 수량이 더 크면 거부(「먼저 재고를 고치세요」). 장부 부족을 판매로 덮지 않는다.
- **되돌리기:** 줄을 `canceled`로 → 차감됐으면 역전표, 옛 장부 행 `voided_at`.
- 수익 화면이 새 채널 값 `karrot`을 표시하는지 계획 단계에서 확인.
- **데이터:** 마이그레이션으로 `erp.orders`·`erp.order_lines` 채널 검사에 `karrot` 추가.

## ④ RG 입고 자동 처리

- **일정:** pg_cron 매일 09:30 KST → `/api/cron/rg-reconcile`(Bearer · `withJobRun('rg-reconcile')` · 텔레그램). **`deduct_enabled = false`면 건너뜀으로 남긴다.**
- **순서:** RG 주문 수집 1회(`collectOrders(['coupang_rg'])`) → RG 실재고(`fetchRgStock`) vs 원장 RG(`rgLedgerBySku`) SKU별 비교.

| 경우 | 처리 |
|---|---|
| 실재고 > 원장, 입고중 > 0 | `min(차이, 입고중)`만큼 `rg_inbound → rg` 자동 이동(기존 `rg-arrive` 코드, 먼저 보낸 것부터). 키 `rgauto:<KST 날짜>:<sku>` |
| 입고중을 채우고도 남는 증가 | 알림 「보낸 기록 없는 증가」 |
| 실재고 < 원장 | **2회 연속**일 때만 알림(분실·파손 의심) |
| 연결 안 된 RG 번호에 재고 | 알림(Wing에 안 보이는 RG 전용 상품 포착) |
| 입고중 7일 초과 발송분 | 알림. 기준일 = 「RG 보내기」 기록일(`rgship` 전표 `occurred_at`) |

- **안전장치:** 설정 `rg_auto_arrive_enabled`(기본 false). 꺼져 있으면 「옮길 예정」만 보고한다. 배포 뒤 3회 보고를 사용자가 보고 승인하면 켠다.
- **화면:** 재고현황 RG 대조 영역에 마지막 자동 실행 결과(자동 이동 · 확인 대기). 사람의 「반영」은 유지.
- **데이터:** `erp.rg_recon_snapshots(run_id, run_at, sku_id, ledger, actual)` · `erp.settings` 행 `rg_auto_arrive_enabled`.

## 하지 않는 것

이상 SKU 표시 · 기초 이전 옛 장부 복구(RG 무효 1,062 · 네이버 누락 · Wing 무접두 중복) · 다운로드 쿠폰 추정 · 쿠팡 판매자배송 배송 후 반품 자동 역전표 · 채널 재고 전송(1-D) · 주문 화면 교체(2단계) · 새 판매 채널 어댑터.

## 열린 질문

- 쿠팡 발주서 `discountPrice`가 판매자 부담 즉시할인과 같은 값인가 — ② 첫 작업에서 실측
- 토스 `originPrice − price`가 판매자 부담인가(토스 부담 프로모션이 섞이는가)
- RG 전용 등록상품(Wing 목록에 안 보임)이 앞으로도 생기는가 — ④의 「연결 안 된 RG 번호」 알림이 포착한다
