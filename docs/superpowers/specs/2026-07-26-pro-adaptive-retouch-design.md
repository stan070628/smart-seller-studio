# PRO 실사진 적응형 보정 (1단계-B) 설계 문서

> 작성일: 2026-07-26
> 상태: 승인됨 (구현 대기)
> 선행: PRO 촬영 가이드 Phase 1~4 (병합됨, 브랜치 `feat-pro-shot-retouch`)
> 큰 그림: "PRO 상세페이지를 외주업체 수준으로" 3단계 중 1단계-B. 1단계-A(스토리라인 엔진)와 독립 트랙이며 병렬 진행 가능.

## 0. 맥락

Phase 4가 실사진 보정을 도입했으나 **Sharp 고정 파라미터**다(`retouch-photo/route.ts:45~50`):

```ts
sharp(inputBuf)
  .rotate()
  .modulate({ brightness: 1.04, saturation: 1.06 })
  .sharpen({ sigma: 0.6 })
```

모든 사진에 동일한 값을 먹인다. 어두운 사진도 밝은 사진도 1.04배다. 사실상 "약간의 화사함" 이상은 못 한다.

사용자가 지목한 불만 네 가지:

1. 배경이 지저분함
2. 어둡거나 색이 이상함
3. 상세페이지 톤과 안 맞음
4. 구도·수평이 어긋남

## 1. 이번 범위가 좁아진 이유 (중요)

당초 설계는 네 가지를 모두 다루려 했으나, 코드 검토에서 **배경 관련 설계가 도달 불가능한 경로**임이 드러났다.

### 1.1 모든 ShootSlot은 접사다

`extractDetailCloseupShots`(`src/lib/detail-page/shot-guide.ts:6~16`)는 **`slotType === 'detail_closeup'`인 슬롯만** 추출하고, `ShootSlot`은 여기서만 생성된다(`page.tsx:331~357`). "전체컷(제품 단독)" 슬롯은 촬영 가이드 파이프라인에 존재하지 않는다.

접사 사진에 누끼(배경 분리)를 돌리는 것은 무의미하다 — 원단 텍스처 접사는 배경이 곧 제품이다. 따라서 **배경 정리·교체는 shot-guide가 전체컷 슬롯을 생성하도록 확장된 뒤에야 가능하다.** 그 확장은 3단계(촬영 제안 루프)의 작업이다.

### 1.2 합성 경로 재사용은 "배경 교체"가 아니다

`compositeProductOnBackground`(`generate-scene-image/route.ts:300~362`)는 누끼를 **배경 하단 중앙, 높이 58%, 접지선 88%에 강제 배치하고 가짜 접지 그림자를 합성한다**(`route.ts:317~353`). 사용자가 잡은 구도·앵글·프레이밍은 전부 폐기된다.

이 경로를 "내 사진의 배경 교체"라고 부르면 사용자 기대와 어긋난다. 실제로는 **"내 제품 누끼로 AI 씬을 새로 생성"** 이며, 기존 AI 씬 생성과 결과물이 사실상 같다. 3단계에서 이 기능을 제공하더라도 UX 문구를 정직하게 써야 한다.

부수적으로 `selectCompositeCutout`·`compositeProductOnBackground`·`measureOpaqueRatio`는 모두 `route.ts`의 module-private 함수라 공용 lib 추출 리팩터링이 선행돼야 하는데, 이는 Phase 4가 명시한 격리 원칙(`generate-scene-image` 미변경)과 충돌한다.

### 1.3 누끼 임계값이 촬영 가이드 사진에 부적합

`CUTOUT_MAX_OPAQUE_RATIO = 0.6`(`generate-scene-image/route.ts:139`)의 원래 용도는 "멀티 제품 콜라주 감지"다(같은 파일 137~138행 주석). 그런데 촬영 가이드는 클로즈업·프레임 채우기를 지시하므로, **사용자가 잘 찍을수록 불투명 비율이 0.6을 넘어 거부된다.** 배경 기능을 도입할 때 이 임계값 재보정이 필수다.

### 1.4 결론

**이번 범위는 접사 사진의 적응형 노출·색·톤 보정으로 한정한다.** 불만 1번(배경)과 4번(수평)은 다루지 않는다 — 수평은 접사에 수평선 자체가 없어 ROI가 없고, Sharp의 소각도 회전은 캔버스 확장·배경 채움·재크롭이라는 별도 기하 계산을 요구한다.

## 2. Phase 4 원설계와의 관계

Phase 4는 세 가지 근거로 Sharp 고정값을 택했다(`2026-07-26-pro-shot-guide-phase4-design.md`):

- §0: 병렬 세션 원칙 *"어떤 업로드 경로도 사용자 이미지를 자동 편집하지 않음"* → 보정은 명시적 opt-in
- §0: *"방식: **Sharp만**(결정론·자연스러움). AI·합성·배경변경 없음."*
- §⑥ 범위 밖: *"Gemini 배경 정돈(**이번엔** Sharp만)"*

즉 AI 개입은 이미 검토되고 **의도적으로 보류된** 방안이다. 기각 사유는 품질 검증 실패가 아니라 스코프 제약이었고 "이번엔"이라는 표현이 재개를 열어두었다.

**이번 설계는 Phase 4의 두 원칙을 모두 지킨다:**

- **결정론 유지** — 진단을 LLM이 아닌 `sharp().stats()` 기반 계산으로 수행하므로 "같은 입력 → 같은 결과"가 보존된다. 이는 원설계보다 후퇴가 아니라, 고정 상수를 이미지 통계로 대체하는 개선이다.
- **opt-in 유지** — 기존 "AI 보정" 버튼 → before/after → 적용 흐름을 그대로 쓴다. 자동 편집은 없다.
- **격리 유지** — `generate-scene-image`를 변경하지 않는다. 이번 범위에 합성 경로가 없기 때문에 가능하다.

## 3. 설계

### ① 진단은 LLM이 아니라 이미지 통계로

당초 Claude Haiku vision에 `exposureStops`·`colorTempShift`·`tiltDegrees`를 묻는 안을 검토했으나 **철회한다.**

- vision LLM은 "어둡다" 방향 판정은 하지만 stop 단위 정량은 신뢰할 수 없다
- 각도 추정은 1~2도 수준을 감지하지 못하고 환각이 흔하다
- 무엇보다 **필요가 없다** — `sharp().stats()`가 채널별 `mean`/`stdev`/`min`/`max`와 `entropy`를 결정론적으로 제공한다

따라서 **신규 `diagnose-photo` 엔드포인트를 만들지 않는다.** 진단은 `retouch-photo` 내부에서 수행한다. 별도 왕복은 이미지 fetch를 중복시킬 뿐이고, 진단값을 UI에 노출할 계획도 없다.

### ② 적응형 노출 보정

`stats()`의 채널 평균으로 이미지 전체 휘도를 구하고, 목표 휘도와의 비율을 `modulate.brightness`에 넣는다.

```
luma = 0.2126·R̄ + 0.7152·Ḡ + 0.0722·B̄     (0~255)
brightness = clamp(TARGET_LUMA / luma, MIN, MAX)
```

- `TARGET_LUMA`: 이커머스 제품 접사 기준으로 중간톤보다 약간 밝게 설정 (초기값 138, 실물 튜닝 대상)
- `MIN`/`MAX`: 0.85 ~ 1.35. 과보정으로 하이라이트가 날아가는 것을 막는 안전 범위
- 이미 적정 노출인 사진은 비율이 1에 가까워 사실상 무보정이 된다 — 현행 고정 1.04가 모든 사진을 일괄로 밝히던 것보다 안전하다

**하이라이트 클리핑 방어**: `stats()`의 `max`가 이미 250을 넘고 상위 밝기 비중이 크면 `brightness` 상한을 1.0으로 눌러 밝은 사진을 더 밝히지 않는다.

### ③ 화이트밸런스 (gray-world)

형광등 초록끼·백열등 노란끼·그늘 푸른끼를 채널 평균 정규화로 보정한다.

```
gray = (R̄ + Ḡ + B̄) / 3
multipliers = [gray/R̄, gray/Ḡ, gray/B̄]   각각 clamp(0.9, 1.1)
```

sharp 0.34.5의 `linear(multipliers, offsets)`는 **채널별 배열을 지원**하므로 한 번의 호출로 적용된다.

**clamp를 0.9~1.1로 좁게 두는 이유**: 제품 자체가 강한 단색(예: 새빨간 원단)이면 gray-world 가정이 깨져 제품 색을 왜곡한다. 좁은 범위는 조명 캐스트만 걷어내고 제품 고유색은 보존한다. **색이 곧 상품 정보인 도메인이므로 과보정보다 미보정이 안전하다.**

### ④ 톤 매칭 (불만 3번)

상세페이지 팔레트를 보정 목표값에 반영한다.

- 페이지의 `bgStyle`과 섹션 색상에서 페이지가 **웜 톤**인지 **쿨 톤**인지 판정한다
- 웜 페이지면 화이트밸런스 목표를 중립보다 약간 웜 쪽으로(R 계수 +2~3%), 쿨 페이지면 반대로 미세 시프트한다
- 채도는 페이지 톤과 무관하게 `stats().stdev` 기반으로 조정한다 — 대비가 낮은(흐린) 사진만 채도를 올리고, 이미 선명한 사진은 건드리지 않는다

**클라이언트가 톤 정보를 요청에 실어 보낸다.** 서버는 `generatedSections`를 볼 수 없다.

### ⑤ 샤프닝

`stats().sharpness`를 참조해 이미 선명한 사진에는 샤프닝을 걸지 않는다. 현행 고정 `sigma: 0.6`은 폰 사진에 이미 걸린 내부 샤프닝과 겹쳐 가장자리에 링잉을 만들 수 있다.

- `sharpness`가 임계 미만일 때만 `sigma: 0.6~0.8` 적용
- 그 외에는 생략

### ⑥ API 변경

**`retouch-photo`를 확장한다. 신규 엔드포인트는 없다.**

```ts
{
  imageUrl: string,           // 기존
  pageTone?: 'warm' | 'cool' | 'neutral',   // 신규 — ④ 톤 매칭용
  mode?: 'adaptive' | 'legacy'              // 신규 — 기본 'adaptive'
}
```

- `mode: 'legacy'`는 현행 고정 파라미터 경로를 그대로 유지한다. 적응형 결과가 마음에 안 들 때의 탈출구이자 회귀 안전망이다.
- 응답 형태(`{ success, url }`)는 변경하지 않는다 — 클라이언트 `handleRetouch`(`page.tsx:396~413`)가 그대로 동작한다.
- `maxDuration = 60` 유지. 추가되는 것은 `stats()` 호출 한 번뿐으로 지연이 사실상 없다.
- rate limit 10회/분 유지. 외부 API 호출이 늘지 않으므로 재조정 불필요.

### ⑦ 폴백

- `stats()` 호출 실패 → 현행 고정 파라미터(1.04 / 1.06 / 0.6)로 진행. **현재 동작이 최저 보장선이다.**
- 계산된 계수가 유효 범위를 벗어나면 clamp. NaN·Infinity는 1.0으로 대체.
- 원본은 `ShootSlot.retouchedUrl`이 별도 필드라 이미 보존된다(`types/shot-guide.ts:22`). 재보정·원본 복귀 모두 가능하다.

### ⑧ UI

**변경 없다.** 기존 카드별 "AI 보정" 버튼 → before/after 프리뷰(`page.tsx:1035~1052`) → "적용"/"원본 유지" 흐름을 그대로 쓴다.

`retouchPreview` 상태는 `{ index, url }` 단일 쌍이므로 이번 범위에서는 충분하다. 3단계에서 "배경 교체" 같은 복수 후보를 제공하게 되면 그때 구조를 확장한다.

## 4. 범위 밖

- 배경 정리·교체 — shot-guide의 전체컷 슬롯 확장이 선행돼야 함 (3단계)
- 기울기·수평 보정 — 접사에는 수평선이 없어 ROI 없음
- 인물 컷 보정 — 인물 슬롯 자체가 2단계 이후에 생김
- 보정 강도 슬라이더·프리셋 — Phase 4에서 이미 범위 밖으로 선언됨
- 배치 보정
- `retouched/` 고아 파일 정리 — 재보정 시 이전 보정본이 Storage에 누적되나 현행에도 있는 문제이며 별도 과제

## 5. 테스트

### 신규

- 어두운 사진 → `brightness > 1`, 밝은 사진 → `brightness ≤ 1`
- 이미 적정 노출 → 계수가 1 근처(사실상 무보정)
- 색 캐스트가 있는 입력 → 채널 계수가 캐스트 반대 방향
- 강한 단색 이미지 → clamp가 걸려 제품색이 왜곡되지 않음
- `stats()` 실패 시 고정 파라미터 폴백
- 계수 NaN/Infinity 방어
- `pageTone`에 따른 목표값 시프트 방향
- `mode: 'legacy'`가 현행과 동일한 출력

### 회귀

- 응답 형태 불변 — `handleRetouch` 무변경으로 동작
- `generate-scene-image` 미변경 (격리 원칙)

### 실물 검증

폰으로 찍은 접사 샘플(어두운 실내, 형광등, 창가 자연광 3종)에 대해 before/after를 눈으로 확인한다. 자동화 테스트로는 "자연스러움"을 판정할 수 없다.

## 6. 리스크

1. **`TARGET_LUMA` 튜닝** — 초기값 138은 근거 있는 추정치이나 실물로 조정해야 한다. 너무 높으면 전체가 들뜨고 낮으면 개선이 체감되지 않는다.
2. **gray-world 가정 붕괴** — 단색 제품이 프레임을 채우면 화이트밸런스가 제품색을 중립으로 끌어당긴다. clamp 0.9~1.1로 완화했으나 완전 해결은 아니다. 색 왜곡 신고가 나오면 clamp를 더 좁히거나 제품 영역을 제외한 통계로 전환한다.
3. **불만 1·4번 미해결** — 사용자가 지목한 네 가지 중 둘은 이번 범위 밖이다. 배경 문제는 3단계에서 shot-guide 슬롯 확장과 함께 다룬다는 점을 사용자에게 명확히 전달해야 한다.
4. **결정론 원칙 유지 확인** — 이 설계는 LLM을 쓰지 않으므로 Phase 4의 결정론 원칙을 깨지 않는다. 향후 누군가 "배경 정리에 Gemini를 쓰자"고 할 때는 이 원칙을 명시적으로 재검토해야 한다.
