## 문제 정의

현재 상품상세 자동만들기는 버튼 클릭 시 Claude가 HTML 텍스트 구조와 씬 이미지 기획을 병렬 생성하고, 사용자는 이미지 프롬프트만 보이는 StoryboardEditor를 통해 확인한다. 사용자는 Gemini가 이미지를 생성하기 전에 **"각 씬이 어떤 텍스트로 구성되고, 어떤 이미지가 들어갈지"** 한눈에 확인·수정하고 싶지만, 현재 UX에서는 텍스트 섹션 내용(헤드라인, 판매포인트 등)이 숨겨져 있다.

---

## 목표

- **Step 1**: Claude가 생성한 페이지 텍스트 구조 + 씬 이미지 기획을 함께 보여주는 Blueprint 리뷰 뷰 제공
- **Step 2**: 사용자 확인 후 Gemini가 이미지를 생성해 최종 상세페이지 완성
- 참고 UX: `/Users/seungminlee/Desktop/projects/advertise` AutoReel 위저드 (스크립트 작성 → 씬 편집 → 영상 완성)

## 설계

### 전체 흐름

```
버튼 클릭 ("① 기획 생성")
  ↓
Claude 병렬 생성 (기존 유지, 속도 손해 없음)
  ├─ generate-detail-html  → sections (텍스트 구조)
  └─ plan-scene-images     → storyboard (이미지 기획)
  ↓
[ ① 기획 확인 ────────── ② 이미지 생성 ]  ← 위저드 헤더

  DetailPlanReview 컴포넌트 (세로 스크롤 Blueprint 뷰)
  ↓
사용자 확인·수정 후 "② Gemini로 이미지 생성 →" 클릭
  ↓
Gemini 씬 이미지 생성 → 최종 DetailPageEditor
```

---

### 위저드 헤더

AutoReel 스타일의 2단계 스텝 인디케이터.

```
① 기획 확인  ────────────  ② 이미지 생성
(현재 스텝: 파란 원 + 볼드)  (대기 스텝: 회색)
```

- Step 1 완료(이미지 생성 시작) 시 ✓ 표시로 전환
- Step 2 진행 중에는 DetailPageEditor로 전환 (기존 동작 유지)

### DetailPlanReview 컴포넌트

**파일**: `src/components/listing/detail-maker/DetailPlanReview.tsx`

**`SceneStoryboardItem` 타입 확장** (src/types/detail-page.ts):
```ts
export interface SceneStoryboardItem {
  id: string;
  title: string;
  description: string;
  prompt: string;
  sourceImageIndex: number;
  mode: 'ai' | 'cleanup';
  resultUrl?: string;
  sectionId: string | null;  // 추가 — 연결된 DetailSection.id, null이면 매핑 없음
}
```

**Props**:
```ts
interface DetailPlanReviewProps {
  sections: DetailSection[];          // Claude 텍스트 구조
  storyboard: SceneStoryboardItem[];  // Claude 씬 이미지 기획 (빈 배열 허용)
  uploadedUrls: string[];
  isHtmlReady: boolean;               // HTML 생성 완료 여부 (false면 텍스트 로딩 인디케이터)
  isGeneratingScenes: boolean;
  onSectionsChange: (sections: DetailSection[]) => void;
  onScenesChange: (scenes: SceneStoryboardItem[]) => void;
  onGenerate: () => void;             // ② 이미지 생성 트리거
}
```

#### 섹션 카드 종류

**이미지 섹션** (hero, point): 텍스트 + 이미지 기획 함께 표시

```
┌─────────────────────────────────────────────────┐
│  ① HERO                                [섹션타입 뱃지]  │
│  ─────────────────────────────────────────────  │
│  헤드라인: "빠른 아침 루틴을 위한 필통"          │
│  서브: "180도 완전 오픈형 구조"                  │
│  ─────────────────────────────────────────────  │
│  🎨 이미지 기획                                  │
│  흰 책상 위에 필통, 자연광, 45도 각도...          │
│  [이미지1] [⚡AI / ✨Cleanup]                   │
└─────────────────────────────────────────────────┘
```

**텍스트 전용 섹션** (selling_points, spec_table, features 등): 텍스트 내용만

```
┌─────────────────────────────────────────────────┐
│  ② SELLING POINTS                [섹션타입 뱃지]  │
│  • 가볍다 (150g, 경쟁사 대비 30% 가벼움)         │
│  • 180도 완전 오픈 — 내용물 한눈에               │
│  • 내구성 높은 옥스포드 원단                     │
└─────────────────────────────────────────────────┘
```

#### 섹션-스토리보드 매핑 규칙

- hero/point 타입 섹션 순서 ↔ storyboard 씬 순서로 1:1 매핑
- 텍스트 전용 섹션은 storyboard 연결 없음
- 매핑 함수: `getImageSectionIndex(sections, sectionId)` → storyboard 인덱스 반환

#### 인라인 편집

- 헤드라인/서브헤드라인: 클릭 시 input으로 전환, blur 시 sections 업데이트
- 이미지 프롬프트: textarea 직접 편집
- 소스 이미지 선택: 썸네일 클릭으로 변경 (기존 StoryboardEditor 방식 유지)
- 모드 토글 (AI ↔ Cleanup): 기존 방식 유지

### DetailMakerClient 변경

#### step 상태 머신 (단일 소스)

`detailStep` 상태를 **단일 렌더 분기 소스**로 사용. 기존 `sections.length > 0` / `storyboard !== null` 파생 분기는 **모두 제거**한다 (두 시스템 공존 시 이중 진실 공급원 버그 발생).

```tsx
type DetailStep = 'idle' | 'generating' | 'planning' | 'editing';
const [detailStep, setDetailStep] = useState<DetailStep>('idle');
```

| step | 렌더 | 설명 |
|------|------|------|
| `idle` | EmptyState (빈 화면) | 초기 상태 |
| `generating` | EmptyState (스피너) | 기획 생성 중 |
| `planning` | DetailPlanReview | storyboard 도착 후 리뷰 |
| `editing` | DetailPageEditor | 이미지 생성 후 최종 에디터 |

#### step 전환 타이밍

- "① 기획 생성" 클릭 → `setDetailStep('generating')`
- storyboard 도착 시 → `setDetailStep('planning')` ← **HTML 완료를 기다리지 않음**
- HTML 완료는 background에서 sections를 채울 뿐, step을 자동 전환하지 않음 (Blueprint 단계 건너뜀 방지)
- "② Gemini로 이미지 생성" 클릭 → `setDetailStep('editing')`
- "① 기획 다시 생성" 클릭 → sections/storyboard/generatedHtml 초기화 + `setDetailStep('generating')`

#### storyboard 실패 시 Fallback

storyboard 실패 + HTML 성공(sections 존재) 케이스:
- `setDetailStep('planning')` + `storyboard = []` (빈 배열)로 처리
- DetailPlanReview에서 텍스트 섹션은 표시하되, 이미지 기획 영역에 "이미지 기획 생성 실패 — 직접 입력하거나 재시도하세요" 안내

#### 섹션-스토리보드 ID 기반 매핑

현재 인덱스 기반 매핑을 ID 기반으로 전환해 DnD 재정렬 및 길이 불일치 시 안전성 확보.

`plan-scene-images` 호출 결과를 클라이언트에서 sections에 연결할 때 `sectionId`를 부여:

```ts
// storyboard 생성 후, sections의 이미지 섹션 순서에 맞게 sectionId 할당
const imageSections = sections.filter(s => s.type === 'hero' || s.type === 'point');
const mappedStoryboard = data.scenes.map((scene, idx) => ({
  ...scene,
  id: crypto.randomUUID(),
  mode: 'ai' as const,
  sectionId: imageSections[idx]?.id ?? null, // 섹션 수보다 씬이 많으면 null
}));
```

- `sectionId: null`인 씬은 DetailPlanReview에서 "연결 없음" 상태로 표시 (이미지 생성 대상에서 제외)
- 섹션보다 씬이 적은 경우, 매핑 안 된 섹션은 storyboard 없이 fallback 로테이션 유지 (기존 동작)
- DnD 재정렬 시 sections와 storyboard **둘 다** onSectionsChange + onScenesChange로 동기화

---

**DnD 순서 변경 동기화 규칙:**
이미지 섹션 카드를 재정렬하면:
1. `onSectionsChange(reorderedSections)` 호출
2. `onScenesChange(reorderedStoryboard)` — sectionId 기준으로 storyboard도 같은 순서로 재정렬

입력 패널 버튼: `"스토리라인 구성"` → `"① 기획 생성"`

## 성공 기준

- 버튼 클릭 후 텍스트 섹션 내용 + 이미지 프롬프트가 Blueprint 카드로 함께 보임
- 텍스트(헤드라인)와 이미지 프롬프트를 모두 인라인 편집 가능
- "② Gemini로 이미지 생성" 클릭 후 기존과 동일하게 DetailPageEditor로 전환
- 위저드 헤더가 현재 단계를 명확히 표시

## 범위 제외

- API 변경 없음 (sectionId 매핑은 클라이언트 전용 필드)
- 텍스트 전용 섹션(selling_points, spec_table 등) 인라인 편집은 v1 읽기 전용. 카드 하단에 "상세 편집은 다음 단계에서 가능합니다" 안내 추가
- 씬 추가/삭제는 v1 포함 (기존 StoryboardEditor 동작 흡수)
- 위저드 헤더 step 클릭 네비게이션 (editing → planning 되돌아가기)은 v1 제외, 대신 "① 기획 다시 생성" 버튼으로 대체
