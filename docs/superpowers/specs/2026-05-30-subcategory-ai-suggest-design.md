# 소분류 AI 추천 — 설계 문서

Generated by /brainstorming on 2026-05-30
Status: APPROVED

---

## Problem Statement

소싱 캘린더의 소분류는 `src/lib/categories.ts`에 하드코딩되어 있다.
사용자가 직접 추가/삭제할 수 있지만, 어떤 소분류를 추가해야 할지 모르는 경우가 많다.
AI가 대분류 기반으로 소싱 관점에서 유망한 소분류를 자동 추천하면, 탐색 범위를 넓히는 데 드는 시간을 줄일 수 있다.

---

## Solution

대분류 탭 오른쪽 끝에 **"✦ 소분류 AI 추천"** 버튼을 추가한다.
클릭 시 Claude Haiku가 해당 대분류의 소싱 유망 소분류 6~8개를 생성하고, 기존 소분류 목록을 즉시 교체한다.

## API

### POST `/api/calendar/suggest-subcategories`

Request:
```json
{
  "parentCategory": "잡화",
  "currentSubcategories": ["텀블러", "머그컵", "물병", "에코백", "우산", "지갑", "파우치"]
}
```

Response:
```json
{
  "subcategories": [
    { "id": "ai-보온병-1748600000000", "name": "보온병" },
    { "id": "ai-캠핑컵-1748600000001", "name": "캠핑컵" }
  ],
  "suggestedAt": "2026-05-30T14:00:00Z"
}
```

#### Claude 프롬프트

```
System:
당신은 쿠팡 소싱 전문가입니다.
주어진 대분류에서 현재 트렌드에 맞는 소분류를 추천합니다.
선별 기준:
- 쿠팡에서 단품으로 판매 가능한 상품 카테고리
- 너무 넓거나 좁지 않은 적절한 범위 (예: "텀블러" 적합 / "주방용품" 너무 넓음 / "분홍 텀블러" 너무 좁음)
- 브랜드명 제외
반드시 JSON 배열 형식만 반환하세요.

User:
대분류: {parentCategory}
현재 소분류: {currentSubcategories.join(', ')}

위 대분류에서 소싱 관점으로 유망한 소분류 6~8개를 추천해 주세요.
현재 소분류와 중복되지 않게, 새로운 관점으로 추천해 주세요.
JSON 배열만 반환: ["보온병", "캠핑컵", ...]
```

모델: `claude-haiku-4-5-20251001`

ID 생성 규칙: `ai-${name}-${Date.now() + index}` (서버에서 생성)

#### 에러 처리

| 상황 | 처리 |
|------|------|
| ANTHROPIC_API_KEY 없음 | 접미어 조합 폴백: `${parentCategory} + ["용품", "소품", "세트", "미니", "대형", "휴대용"]` |
| Claude API 실패 | 동일한 접미어 조합 폴백 반환 |
| parentCategory 없음 | 400 에러 반환 |

## UI

### 버튼 위치

대분류 탭 행 오른쪽 끝 (현재 선택된 대분류에 대한 액션임을 명확히 전달).

```
┌─────────────────────────────────────────────────────────────┐
│ [잡화] [뷰티/위생] [생활용품] ...    [✦ 소분류 AI 추천]     │
├─────────────────────────────────────────────────────────────┤
│ [텀블러] [머그컵] [물병] ...  [+ 추가]                      │
```

### 상태

- **기본**: `✦ 소분류 AI 추천` (보라색 테두리, 연보라 배경)
- **로딩**: `추천 중...` (비활성화, 기존 소분류 흐리게)
- **완료**: 새 소분류가 보라색으로 하이라이트되어 표시 (1회성)

### 동작

1. "✦ 소분류 AI 추천" 클릭
2. `suggestLoading = true`, 기존 소분류 흐리게 표시
3. `POST /api/calendar/suggest-subcategories` 호출
4. 응답받은 subcategories로 해당 대분류의 소분류 교체
5. `persistCategories(updated)` → localStorage 저장
6. `activeSubId / keywords / results` 초기화 (선택 상태 리셋)
7. `suggestLoading = false`

확인 다이얼로그 없음 — 즉시 교체.

## localStorage 영향

소분류 교체 시 기존 소분류의 캐시 키(`sourcing-calendar-recommend-{oldSubId}`, `sourcing-calendar-result-{oldSubId}`)는 자동으로 무효화됨 (orphan 상태). 명시적 삭제는 하지 않음.
