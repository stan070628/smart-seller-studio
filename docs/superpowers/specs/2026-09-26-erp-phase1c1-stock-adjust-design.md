# ERP 1-C1 — 재고 수정·기초재고·입고/RG 기록 설계

> **TL;DR** 원장(1-B)을 「살아 있게」 만든다. 사람이 PC·휴대폰에서 재고를 고치고(기본 「지금 개수」), 그 첫 입력이 곧 기초재고가 된다. 코스트코 영수증 확정과 RG 보내기가 원장에 함께 기록되고, RG는 쿠팡 재고 API와 대조해 확인 후 반영한다. 판매 차감은 1-C2다.

- 작성: 2026-09-26 · 상위 설계: `2026-09-25-erp-restructure-design.md` · 선행: 1-B(PR #21, 원장 비어 있음)
- 결정 기록: `2026-09-26-erp-phase1c1-stock-adjust-decisions.md`

## 사용자 결정 (2026-09-26)

| # | 결정 |
|---|---|

## 1. 재고 수정 (조정 전표)

**입력:** SKU · 위치(`self` | `rg_inbound`) · 방식(`count` 지금 개수 | `delta` ±수량) · 사유 · 메모.

| 방식 | 계산 | 전표 |
|---|---|---|
| `count` | `차이 = 입력 − 원장 재고(그 위치)` | 차이 < 0 → `postConsume(kind='adjust')`(FIFO) · 차이 > 0 → `postLotCreate(kind='adjust')` · 0 → 기록 없음 |
| `delta` | 입력 그대로 | 부호에 따라 위와 같다 |

**사유 코드:** `count_diff`(실사차이) · `damage`(파손) · `loss`(분실) · `sample`(샘플·증정) · `return_in`(반품입고) · `other`(기타). 원장에 `reason` 칸을 더한다(마이그레이션 115, `kind='adjust'`면 필수).

**늘어난 재고의 단가**(새 lot) — 먼저 찾은 것을 쓰고, 화면은 값을 보여주고 고칠 수 있다.
1. 그 SKU의 가장 최근 lot 단가(위치 무관)
2. 옛 `cost_entries`(SKU의 `legacy_product_cost_ids`)의 최근 단가
3. 없으면 입력 필수

**되돌리기:** 조정 한 건 = 멱등키 하나(`adj:<uuid>`). 입출 이력의 「되돌리기」가 `reverse()`를 부른다. 되돌린 뒤 다시 적으면 새 조정이다.

**동시성:** 화면이 본 재고와 저장 시점 재고가 다를 수 있다 → `count` 요청은 화면이 본 값(`expected`)을 함께 보내고, 서버가 잠금 뒤 다시 읽어 다르면 409로 거부한다(다시 보고 적게 한다).

**기초재고 = 첫 조정.** 원장이 빈 SKU의 첫 `count`는 사유 `opening`, 전표 `kind='opening'`으로 기록한다. 처음 기초재고가 들어갈 때 `sync_cursors.ledger_cutover`를 그 시각으로 적는다(이미 있으면 두지 않는다 — 1-C2 소급의 시작점).

## 2. RG 대조

- 버튼 하나: 쿠팡 RG 재고 API(`getRocketGrowthInventories`)를 읽어 SKU별 `실재고 − 원장 RG`를 보인다(1-B `rgQtyBySku`·`reconcileRg` 재사용, 보관 SKU·미매핑 vid는 경고).
- 행마다 「반영」 → `rg` 위치 조정 전표(사유 `rg_reconcile`). 늘어나면 단가는 1절 규칙. 일괄 반영은 확인 창(바뀔 SKU 수·증감·평가액).
- 1-C1에서는 **자동 반영하지 않는다.** 판매 차감이 없어 RG 판매가 차이로 보이기 때문이다. 자동 입고 완료(`rg_inbound → rg`)·7일 경보는 1-C2.

## 3. 화면

**PC `/erp/stock` 재고현황**(C11 축소판 · 2단계에서 ERP 틀로 옮긴다)
- 조회조건: 검색(상품·옵션·키) · 재고 있는 것만 · RG 불일치만. KPI: 총재고 · 집 · RG입고중 · RG · 평가액 · RG 불일치.
- 열: 상품 · 옵션 · 집 · RG입고중 · RG(원장) · RG실재고 · 차이 · 단가(최근 lot) · 평가액.
- 집·RG입고중 칸 클릭 → 인라인 편집(지금 개수 · `±` 전환 · 사유). **실사 모드**: 여러 칸을 고치고 한 번에 저장, 저장 전 확인 창.
- 행 클릭 → 우측 패널 입출 이력(전표 종류·수량·단가·사유·메모·시각) + 조정 줄 「되돌리기」.
- 버튼: RG 실재고 대조 · 실사표 불러오기(CSV) · 엑셀↓. 사이드바 「재고·매입 > 재고현황」.
- 스타일은 `E` 토큰 + `erp-ui.tsx`. TanStack은 2단계(지금 도입하지 않는다).

**휴대폰 `/m/stock`**(영수증 화면 틀: 480px · 상단 52px · 하단 고정 버튼)
- 검색 → SKU 카드(집·입고중·RG) → 위치 탭 → 지금 개수(−/+) · 사유 · 메모 → 저장. 최근 수정 5건.

**실사표 불러오기(기초재고)** — 1-B `opening.ts`(`parseCountCsv`·`resolveOpeningCosts`·`rgQtyBySku`) 재사용. 업로드 → 미리보기(수량·평가액·오류) → 확인 → 한 트랜잭션 적재(`kind='opening'`). 원장에 이미 전표가 있는 SKU는 불러오기 대상에서 빼고 「조정으로 고친다」로 안내한다. RG 칸은 업로드 시점 API 값을 쓴다.

## 4. 입고·RG 보내기 연결

**코스트코 영수증 확정 → `self` 입고**
- `erp.purchase_units`를 **품번 : SKU = 1 : N**으로 바꾼다(유니크 `(supplier, supplier_code, sku_id)`, 마이그레이션 115). 첫 적재는 `costco_item_map` → product_cost → SKU(`legacy_product_cost_ids`)로 만들고, 오매핑 의심 2건(693742·888450)은 사용자 확인 후 넣는다.
- 확정 시: 연결 SKU가 1개면 자동, 여러 개면 확정 화면에서 옵션별 수량 분배(합 = 판매단위 수량). 연결이 없으면 SKU 검색으로 고르고 연결을 저장한다.
- 기존 `createCostEntry` 트랜잭션 안에서 `postLotCreate(kind='receipt', unitCost=그 입고의 판매단위 단가, idem='receipt:<receipt_line_id>:<sku_id>')`. 소분은 기존 계산 그대로(팩 단위).

**RG 보내기 → `self → rg_inbound`**
- 기존 `RocketGrowthShipmentModal`·`rg-shipments` 라우트를 SKU 수량 입력으로 확장. 옛 물류비 배분(`cost_entries` 분할)은 그대로 두고, 같은 요청에서 SKU별 `postTransfer(from='self', to='rg_inbound', idem='rgship:<event_id>:<sku_id>')`. Wing 입고 ID는 메모로 남긴다.
- 🔴 기존 라우트는 이벤트 기록을 트랜잭션 **밖**에서 한다(1-B 조사) — 이번에 트랜잭션 안으로 옮긴다.

## 5. 보안 선행

`/api/orders/{coupang,naver,toss}`가 인증 없이 구매자 정보를 반환한다(2026-09-26 탐색) → 1-C1 첫 작업으로 `requireAuth` 추가. 새 `/api/erp/*`도 전부 인증.

## 6. 데이터 변경 (마이그레이션 115)

- `erp.stock_ledger.reason text` + check(허용 코드) + `kind='adjust'`면 필수. 가드 트리거는 insert만 허용하므로 칸 추가는 안전(원장 비어 있음).
- `erp.purchase_units`: 유니크를 `(supplier, supplier_code, sku_id)`로, `sku_id not null`.
- 새 인덱스 없음(조회는 `stock_on_hand` 뷰·`stock_ledger_lot_idx`).

## 7. 검증과 게이트

| 대상 | 방법 |
|---|---|
| 조정 계산·단가 선택·충돌(409) | vitest 순수 함수 |
| API | 가짜 DB 테스트 + 인증 401 테스트 |
| 원장 제약·조정·되돌리기 | 운영 DB 자가시험 확장(롤백 트랜잭션, 기초재고 적재 전까지만) |
| 화면 | 로컬 개발 서버에서 PC·휴대폰 폭 확인(로그인은 사용자) |
| 🔴 **게이트** | 사용자가 실사표 불러오기로 기초재고 입력 → RG 대조 반영 → **원장 RG = 쿠팡 RG 실재고**(1-B 단계 관문) |
