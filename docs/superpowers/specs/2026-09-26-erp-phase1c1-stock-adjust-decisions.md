# ERP 1-C1 설계 — 사용자 결정 기록 (브레인스토밍 진행 중)

> 설계서 본문 작성 전 답을 즉시 적는 작업 파일. 설계서가 나오면 그쪽으로 흡수한다.

| # | 질문 | 사용자 답 (2026-09-26) |
|---|---|---|
| 0 | 계기 | 「재고는 수시로 틀릴 수 있으니 프로그램 안에서 재고 수정하는 기능이 있어야 한다」 · 1-C 계획서를 먼저 쓴다 |
| 1 | 1-C 범위 | **둘로 나눈다** — 1-C1 재고 수정(화면·모바일) + 기초재고 입력 + 입고·RG 보내기 기록 / 1-C2 주문 수집 4채널 + 판매 차감 + 당근 |
| 2 | 수정 화면 | **PC + 휴대폰 둘 다** — PC는 재고현황 표에서 여러 SKU, 휴대폰(/m)은 상품 검색 → 개수 입력. 같은 API |
| 3 | 입력 방식 | **둘 다, 기본은 「지금 개수」**(차이를 계산해 조정 전표) · 보조로 ±수량. 둘 다 사유 선택(실사차이·파손·분실·샘플/증정·반품입고·기타) |
| 4 | 영수증 입고 연결 | **영수증 확정 때 옵션 고르기** — 품번이 SKU 하나면 자동, 여러 옵션이면 확정 화면에서 옵션별 수량 분배, 고른 품번→SKU는 기억 |

## 탐색에서 나온 사실 (2026-09-26)
- RG 판매 무효 1,062건 ≈ 99%가 `rg-bulk-import`의 30일 구간 경계 버그(끝 날짜 배타 → 경계일 누락 → 「응답에 없음」으로 무효). 옛 수익 화면 RG 매출 과소 가능성 — 1-C2에서 수정
- `/api/orders/{coupang,naver,toss}`가 인증 없이 구매자 정보를 반환 — 1-C1 첫 작업 후보
- TanStack Table/Query 미설치, 공용 그리드 없음. 화면은 `E` 토큰 + 손 테이블. `/m`은 480px 단일 열 + 하단 고정 버튼 패턴(영수증)
| 5 | 품목이 많아지면 실사가 힘들다(사용자 지적) → 추가 기능 | **「오늘 셀 목록」(순환 실사) + 「상품 단위로 묶어 보기」**를 1-C1에 넣는다. 「이상한 것만 표시」는 판매 차감이 있어야 의미 있어 1-C2, 바코드 스캔은 SKU 바코드를 채운 뒤 |

## 추가 설계 (2026-09-26)
- **센 기록 `erp.stock_counts`**(마이그레이션 116): `count` 방식 입력은 차이가 0이어도 한 줄 남긴다(SKU·위치·센 수량·원장 수량·시각·조정 전표 id|null). 원장 전표는 여전히 차이가 있을 때만.
- **오늘 셀 목록**: 집(`self`) 위치에서 매일 N개(기본 8). 우선순위 = ① 한 번도 안 센 SKU 중 재고 금액 큰 순 ② 마지막 실사가 오래된 순(같으면 금액 큰 순). 오늘 이미 센 것은 빠진다. 재고 0이고 원장 전표도 없는 SKU는 제외(판매하지 않는 옵션). 날마다 저장하지 않고 요청 때 계산.
- **상품 단위 묶기**: `erp.skus.name`(쿠팡 상품명)으로 묶어 한 줄 = 상품(옵션 수 · 합계 집/입고중/RG/평가액), 펼치면 옵션 행. 옵션 1개 상품은 그대로 한 줄.
